What I've Built

PROJECT 01
Superstore Sales Performance Dashboard
Problem

Sales leadership needed real-time visibility into category performance, regional trends, and product-level KPIs across a large retail dataset.

Solution

Built an interactive Power BI dashboard using the Superstore dataset — including data cleaning via Power Query, DAX measures for KPIs like Sales, Profit, and Orders, and drill-down visualisations across regions and customer segments.

Key Insights

Technology leads in revenue; West region tops in sales; some sub-categories show high sales but low profit — a signal for pricing strategy review.

PROJECT 02
E-Commerce Sales Performance Dashboard
Problem

Raw transactional e-commerce data sat in SQL Server with no structured way to surface revenue trends, top products, or country-level performance.

Solution

End-to-end workflow: SQL for extraction and cleaning → Power Query for transformation → DAX KPIs in Power BI → multi-page dashboard with Decomposition Tree, Key Influencers visual, and interactive slicers by Country and Date.

Key Insights

A small number of products drive most revenue; pricing and quantity strongly predict sales outcomes; repeat customers generate significantly higher lifetime value.

PROJECT 03
Customer Segmentation Dashboard (RFM)
Problem

An e-commerce business lacked visibility into who their most valuable customers were, which customers were at risk of churning, and how purchase behaviour varied across segments.

Solution

Applied the RFM (Recency, Frequency, Monetary) model using SQL to score and classify customers into segments — Champions, Loyal, Potential Loyalists, At Risk, Hibernating. Built a Power BI dashboard with scatter plots, donut charts, and KPI cards. Also produced a formal BRD (Business Requirements Document).

Key Insights

Champions drive the majority of revenue; Potential Loyalists offer strong growth opportunities; higher purchase frequency is the strongest predictor of monetary value.

// My Approach

How I Think About Data

01
Define the Business Question

Every good analysis starts before the data. I identify what decision the analysis needs to support — and what "good" looks like as an outcome.

02
Clean, Structure, Model

Data is rarely clean. I use SQL and Power Query to remove noise, resolve inconsistencies, and shape data into models built for analysis — not just storage.

03
Visualise with Purpose

Dashboards should make decisions easier, not harder. I build visuals that highlight what matters, strip out the noise, and are intuitive for non-technical stakeholders.
